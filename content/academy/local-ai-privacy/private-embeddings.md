<h2>What Are Embeddings?</h2>
<p>An embedding is a list of numbers -- a vector -- that represents the meaning of a piece of text. The word "dog" and the phrase "canine companion" have very different spellings but similar embeddings because they mean similar things. This is the foundation of semantic search: finding documents by meaning, not just keyword matching.</p>
<p>Traditional search (like grep or Ctrl+F) finds exact text matches. Semantic search with embeddings finds conceptually related content. Search for "employee burnout" and find documents about "staff retention challenges" and "workplace wellness programs" even if they never use the word "burnout."</p>
<p>When embeddings are generated by a cloud API, every document you embed is sent to a third-party server. With local embeddings, the model runs on your machine -- your documents never leave.</p>
</div>

<div class="lesson-section">
<h2>Generating Local Embeddings</h2>
<p>Ollama makes local embedding generation trivial:</p>
<pre><code># Pull an embedding model
ollama pull nomic-embed-text

# Generate an embedding via API
curl http://localhost:11434/api/embed -d '{
  "model": "nomic-embed-text",
  "input": "This is my private document content."
}'</code></pre>
<p>The response includes a vector (array of 768 floating-point numbers for nomic-embed-text). This vector is a mathematical fingerprint of that text's meaning.</p>
<p><strong>In Python:</strong></p>
<pre><code>import requests

def get_embedding(text):
    response = requests.post(
        "http://localhost:11434/api/embed",
        json={"model": "nomic-embed-text", "input": text}
    )
    return response.json()["embeddings"][0]

# Embed a document
vector = get_embedding("Quarterly revenue increased 15% year over year.")
print(f"Vector dimension: {len(vector)}")  # 768</code></pre>

<div class="tip-box">
<strong>Chunking matters:</strong> Embedding models have a maximum input length (typically 512-8192 tokens). Split long documents into overlapping chunks of 200-500 words. Overlap by 50 words to preserve context at chunk boundaries. The quality of your chunks determines the quality of your search.
</div>
</div>

<div class="lesson-section">
<h2>Setting Up ChromaDB</h2>
<p>ChromaDB is a lightweight, open-source vector database that runs locally. It stores your embeddings and enables similarity search:</p>
<pre><code># Install ChromaDB
pip install chromadb

# Python: Create a local collection and add documents
import chromadb

client = chromadb.PersistentClient(path="./my_vectordb")
collection = client.get_or_create_collection("documents")

# Add documents (ChromaDB can auto-embed with a configured model,
# or you can provide pre-computed embeddings)
collection.add(
    documents=[
        "Q1 revenue grew 15% driven by new client acquisition.",
        "Employee retention improved after implementing flexible work.",
        "The board approved the new strategic plan for 2026-2028."
    ],
    ids=["doc1", "doc2", "doc3"]
)

# Search by meaning
results = collection.query(
    query_texts=["financial performance"],
    n_results=2
)
print(results["documents"])
# Returns the revenue doc first -- semantic match!</code></pre>

<p><strong>Alternative: SQLite with vector extension.</strong> If you prefer a single-file database, sqlite-vss (SQLite Vector Similarity Search) adds vector search to SQLite. Lighter weight than ChromaDB, but requires more manual setup.</p>
</div>

<div class="lesson-section">
<h2>Building Document Search</h2>
<p>Here's the complete pipeline for searching your private documents:</p>
<p><strong>Step 1: Ingest.</strong> Read your documents (PDFs, text files, markdown). Split into chunks.</p>
<p><strong>Step 2: Embed.</strong> Generate embeddings for each chunk using Ollama.</p>
<p><strong>Step 3: Store.</strong> Save chunks and their embeddings to ChromaDB.</p>
<p><strong>Step 4: Query.</strong> When you search, embed the query, find the most similar chunks, return them.</p>

<div class="demo-container">
<h4>Complete Search Pipeline</h4>
<pre><code>import chromadb
import requests
import os

def embed(text):
    r = requests.post("http://localhost:11434/api/embed",
        json={"model": "nomic-embed-text", "input": text})
    return r.json()["embeddings"][0]

def chunk_text(text, size=400, overlap=50):
    words = text.split()
    chunks = []
    for i in range(0, len(words), size - overlap):
        chunks.append(" ".join(words[i:i + size]))
    return chunks

# Setup
client = chromadb.PersistentClient(path="./private_search")
collection = client.get_or_create_collection("docs")

# Ingest a folder of text files
for filename in os.listdir("./my_documents"):
    with open(f"./my_documents/{filename}") as f:
        text = f.read()
    for i, chunk in enumerate(chunk_text(text)):
        collection.add(
            documents=[chunk],
            embeddings=[embed(chunk)],
            ids=[f"{filename}_{i}"],
            metadatas=[{"source": filename}]
        )

# Search
query = "What were our Q3 financial results?"
results = collection.query(
    query_embeddings=[embed(query)],
    n_results=3
)
for doc, meta in zip(results["documents"][0],
                      results["metadatas"][0]):
    print(f"[{meta['source']}] {doc[:100]}...")</code></pre>
</div>

<div class="lesson-section">
<h2>Optimizing Search Quality</h2>
<p>Raw vector search is good. With a few optimizations, it becomes great:</p>
<p><strong>Metadata filtering:</strong> Add metadata like date, document type, and author. Filter searches to specific categories before running similarity.</p>
<p><strong>Hybrid search:</strong> Combine semantic search with keyword search. Some queries need exact term matching (invoice numbers, names) while others need meaning matching (concepts, themes). Use both.</p>
<p><strong>Re-ranking:</strong> Retrieve the top 10 results by embedding similarity, then use a local LLM to re-rank them by relevance to the original query. This catches cases where embedding similarity doesn't perfectly match query intent.</p>
<p><strong>Collection management:</strong> Keep separate collections for different document types (financial, HR, program). This improves search precision and lets you control access per collection.</p>

<div class="callout">
<strong>The privacy guarantee:</strong> In this entire pipeline, data flows from your documents to your local embedding model to your local database. At no point does any content leave your machine. This is the foundation for privacy-first AI -- and it's the building block for the RAG systems we'll build in the next lesson.
</div>
